# PPT 美化技能（PPT Beautification Skill）

把“内容正确但视觉粗糙”的商务 PPT，从**资料存档**改造成**视觉论证**。

> 美化不是换配色、加图标，而是把“资料堆积”改写成“主张—证据—含义”的视觉论证。

这个仓库是一个可复用的 Agent Skill：包含方法论、11 组真实 before/after 拆解、版式原型、设计令牌和交付检查清单。适用于咨询汇报、战略规划、行业研究、经营分析、融资路演等场景。

---

## 这个技能解决什么问题

很多 PPT 的问题不是“不好看”，而是：

- 标题写的是“行业概况”，不是这页的结论；
- 信息关系是“并列的七段话”，却用七个一样的灰框；
- 图表没有直接标注，读者要在图例和正文之间来回找；
- 颜色只是装饰，不编码“已发生/预测”“重点/次要”“风险/机会”；
- 每页版式都不一样，像 20 个模板拼在一起。

技能的核心工作流是：

```text
冻结事实 → 行动标题 → 判断信息关系 → 选版式原型
→ 网格/层级/留白 → 重做图表与表格 → 收口校验
```

三条铁律：

1. **先删后美**：不承载论点的元素删除、降级或移到附录。
2. **先结构后装饰**：先判断对比、趋势、流程、地理、构成、阶段，再选图形。
3. **颜色和图形必须编码含义**：酒红 = 重点/已发生/风险；青绿 = 能力/预测/次要。

### `SKILL.md`

技能主入口，包含：

- 适用/不适用边界；

11 组真实对照的逐页拆解，每组按四段写：

1. 原稿问题；

## 安装

### DeepSeek Harness（DSH）

把整个 `ppt-beautification` 文件夹放到：

```text
~/.dsh/skills/ppt-beautification/
```

刷新会话后，技能目录里会出现 `ppt-beautification`。使用时直接说“美化这页 PPT / 改版这份汇报 / 做 before-after 对比”。

### 其他支持 `SKILL.md` 的 Agent

把仓库根目录作为一个 skill 目录放入对应 skills 路径，保留 `SKILL.md` 与 `references/` 的相对结构即可。`SKILL.md` 的 YAML frontmatter 已包含 `name` 与 `description`。

### 手动使用（不安装）

把 `SKILL.md` 和 `references/` 一起发给模型，要求它：

```text
请按 SKILL.md 的六步工作流改版这页 PPT。
先给行动标题和版式原型，再动手排版。
不要改变事实与数字；缺失信息标【待补】。
```

## 快速使用

### 场景 1：单页急救（10 分钟）

```text
这页信息太散。请：
1) 写一个带判断的行动标题；
2) 判断这页的信息关系（对比/趋势/流程/地理/构成）；
3) 选一个版式原型；
4) 给出 3–4 个模块的分组和每块的一句话；
5) 指出必须删掉的内容。
```

### 场景 2：整份汇报改版（60 分钟）

```text
按 SKILL.md 的流程处理这份 12 页汇报：
先输出“页面清单 + 每页行动标题 + 版式原型 + 保留/删除/待补”，
我确认后再逐页排版。
```

### 场景 3：只修图表

```text
按“图表即论证”原则重做这张图：
直接标注关键数据、只高亮一个结论点、去掉网格/阴影/3D，
图旁加一句“所以呢”。
```

### 场景 4：建立模板系统

```text
为这份汇报建立母版：
16:9、12 栏网格、页边距 0.6 in、
标题 26 pt / 正文 11 pt、
酒红-青绿-米白语义色、
页脚含数据来源与页码。
先做一页封面、一页结论页、一页图表页作为样板。
```

## 11 组对照，提炼出的 9 个设计动作

| # | 设计动作 | 一句话 |
|---|---|---|
| 1 | 结论先行 | 标题写判断，不写主题 |
| 2 | 关系先于版式 | 先判断信息关系，再选图形 |
| 3 | 3–4 块 MECE | 一页只承担一个论证任务 |
| 4 | 网格与等距 | 用不可见的线约束可见的元素 |
| 5 | 语义色 | 颜色编码含义，60-30-10 |
| 6 | 图表即论证 | 直接标注、单点高亮、图旁注释 |
| 7 | 表格卡片化 | 把单元格变成“判断卡” |
| 8 | 视觉隐喻 | 地图、S 曲线、循环、环形、时间线 |
| 9 | 模板系统 | 母版、主题色、页脚、图表预设 |

底层依据：格式塔分组、前注意属性、认知负荷、数据墨水比、叙事证据链。

## 一个必须说明的前提

这 11 组对照里，很大一部分提升来自**内容重构**，而不只是视觉装饰：补充了客户分层、决策矩阵、增长驱动、阶段分组、结论句。

因此，美化项目必须允许“改内容结构”；只做皮肤，效果一定有限。

另外，对照图下排的“美化版”仍存在拼写/占位符/口径问题（如 `withdifferent`、`Here you can write...`）。本技能提炼的是结构、层级、图表标注和系统化方法，**不包含**这些文案与数据疏忽；正式交付前仍需做事实与文字校验。

## 适用与不适用

**适用**

- 咨询/战略/行研/经营分析/融资路演类 PPT；
- 内容基本正确，但版式散、文字多、图表默认、层级弱的草稿；
- 需要从“能看”提升到“能说服人”的 before/after 改版；
- 需要建立可复用的页面模板与视觉规范。

**不适用**

- 纯品牌视觉设计、Logo/VI、动画特效；
- 内容本身尚未想清楚，指望靠美化解决逻辑问题；
- 需要伪造数据、夸大结论、隐藏不利信息的场景。
